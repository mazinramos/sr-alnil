# ADD_CHAPTER — إضافة فصل جديد إلى «سرّ النيل» (مثال مكتمل: الفصل 6)

> **ملاحظة صريحة قبل البدء:** المحتوى (المستويات والألغاز) يُضاف اليوم بلا تعديل على المحرّك ويُفحَص آلياً. لكن **خريطة الرحلة والخاتمة وحقيبة الرموز ما زالت مبنية على 5 فصول**، فالفصل 6 لن يظهر كمحطة قبل أن ينفّذ B بنود `docs/EXPANSION_GAPS.md`. إلى ذلك الحين تستطيعين اختبار الفصل الجديد مباشرةً بالرابط `#/chapter/6` و`#/level/c6-l1` (يُفتح بعد إكمال آخر مستوى في الفصل 5).

## 0) قرارات تُكتب قبل أي ملف (10 دقائق)
| القرار | مثال للفصل 6 |
|---|---|
| العنوان والمكان | «مرفأ الريح» / ميناء قديم |
| قصة الفصل بجملتين | بلا كشف أي حل |
| الشخصيات الجديدة (إن وُجدت) | معرّف لاتيني قصير + الاسم العربي + الدور |
| رمز الفصل | اسم + معنى (مثل: الميزان = العدل والحساب) |
| ما تستعمله الألغاز الأخيرة من رموز الفصول السابقة | يُدوَّن في SYMBOLS.md |
| صورة قطعة الخريطة | انظري §6، فهذا قرار لم يُحسم بعد للفصل 6+ |

## 1) توليد ملف الفصل من القالب
```bash
cd artifacts/nile-secrets
node scripts/new-chapter.mjs 6
```
- ينتج `src/content/chapters/ch6.ts` من `src/content/chapters/_template.ts.txt` بسبعة مستويات، كلٌّ بنوع لغز مختلف.
- لا يكتب فوق ملف موجود (يتوقف برسالة). لتجربة التوليد دون لمس الـ repo: `--out /tmp/x`.
- الملف الناتج **يعمل كما هو** (يمرّ الفاحص ويُلعَب) لكن نصوصه مؤقتة وعليها علامة «غيّري».
- لا حاجة لتسجيل الفصل في أي مكان: `engine/content.ts` يجمع كل `chapters/ch*.ts` تلقائياً. اسم `_template.ts.txt` لا يطابق النمط فلا يُحمَّل.

## 2) قواعد الملف (يفرضها `npm run test:content`)
- اسم الملف `chN.ts`، و`id` الفصل = N.
- `id` المستوى `c6-l3` حرفياً = `c{chapter}-l{index}`، و`index` من 1 إلى 7.
- المستوى 7 بوس: `isBoss: true` و`reward: { id, label }`. وأي بوس بلا `reward` خطأ.
- `hints`: ثلاثة نصوص بالضبط، والثالث وحده يجوز أن يكشف الحل. اقتبسي **نص** الخيار لا حرفه (الواجهة لا تعرض حروف الخيارات).
- `dialogue` من 2 إلى 4 أسطر. `clues` دليلان على الأقل والأفضل 2–3 (الرابع تحذير فقط).
- `clue.id` فريد في اللعبة كلها؛ استعملي `c6-l3-k1`.
- `background` يبدأ بـ `/art/`.
- ترتيب العمل المقترح لتسليم مبكر: **الطبقة A أولاً (l1 وl4 وl7)** ثم الباقي، فهي التي تُرسَم صورها أولاً.

### قواعد جودة لا يفحصها الآلي (راجعيها بنفسك)
1. الحل **وحيد**: تحقّقي بالحصر (جدول 3×3 = 6 احتمالات، ميزان: كل المجموعات ضمن `maxItems`).
2. الحل **غير مكتوب** في النص الظاهر (العنوان، الحوار، الهدف، التلميحين 1 و2).
3. الأدلة وحدها تكفي لاستنتاج الحل. لا لغز يُحلّ بالتخمين: ≥100 احتمال أو دليل مكتوب.
4. كلمات `cipher` لا تتعارض مع كلمات فصول أخرى (محجوزة: «ذاكرة» في c5-l6، «الميزان» في c3-l7، «النهر يعود» في c4-l3).
5. اللهجة: يونس وحليمة سودانية خفيفة؛ النص الروائي بفصحى بسيطة.

## 3) `mapPiece` والمكافأة
```ts
mapPiece: { id: "map-piece-6", label: "قطعة الخريطة السادسة" },   // في الفصل
reward:   { id: "map-piece-6", label: "قطعة الخريطة السادسة" },   // في c6-l7 (نفس القيمة)
```
- المعرّف فريد عبر الفصول (الفاحص الحالي لا يتحقق من تفرّده بين الفصول، فراجعيه).
- منح **الرمز** تلقائي عند إكمال البوس (`engine/symbols.ts`)، وليس عبر `reward`.

## 4) الشخصيات الجديدة
الملف `src/engine/characters.ts` (ملك B) فيه نوع `CharacterId` وجدول `CHARACTERS`. لإضافة «ملاح» مثلاً:
```ts
export type CharacterId = /* … الحالية … */ | "malah";
malah: { id: "malah", name: "ربّان الريح", role: "الملاّح" },
```
- `Level.character` = المعرّف (`"malah"`). و`dialogue[].speaker` = **الاسم العربي حرفياً** كما في `CHARACTERS`؛ المحرّك يربط الصورة بتطابق الاسم، ولو اختلف حرفٌ واحد يستعمل صورة `level.character` بصمت.
- صورة البورتريه: `public/art/chars/malah-neutral.webp` (768×768 شفافة، ≤200KB). التعابير الإضافية `malah-smiling.webp` وغيرها اختيارية.
- لو غابت الصورة يعرض المحرّك الحرف الأول من الاسم، فلا انهيار.

## 5) الخلفيات والأيقونات والصور الخاصة
| النوع | المسار | المقاس | الوزن |
|---|---|---|---|
| خلفية مستوى | `public/art/c6/l1.webp` … `l7.webp` | 1536×1024 (3:2) | ≤250KB |
| أيقونة لغز | `public/art/items/{id}.webp` | 256×256 شفافة | ≤40KB |
| أيقونة رمز الفصل | `public/art/items/symbol-c6.webp` | 256×256 شفافة | ≤40KB |
| بورتريه | `public/art/chars/{id}-{mood}.webp` | 768×768 شفافة | ≤200KB |
| صورة لغز خاصة (مثل tiles) | `public/art/c6/l2-puzzle.webp` | 1024×1024 | ≤250KB |
- `Item.icon` يقبل **معرّفاً** (`"bead-blue"` ← `/art/items/bead-blue.webp`) أو مساراً يبدأ بـ `/`. عند غياب الصورة يظهر `label` نصاً.
- لتقليل الجهد: خلفية واحدة `l1` للفصل مع `focal: { x, y, zoom }` في بقية المستويات (CONTRACT §5).
- التوليد: أنكورات وقواعد F في `docs/prompts/PROMPTS_00_INVENTORY.md`؛ التحويل `cwebp -q 80`؛ و`npm run optimize-images` لتصغير الموجود.
- `npm run report:assets` يكتب `docs/MISSING_ASSETS.md` بكل صورة مستعملة وغير موجودة، بما فيها `symbol-c6` تلقائياً من المستوى 7.

## 6) صورة قطعة الخريطة (قرار مفتوح للفصل 6+)
- الفصول 1–5 تقتطع قطعتها من `ui/map-full.webp` بشبكة 3×2 (`#cell=n`، الخلية 6 زخرفية). لا توجد خلية سابعة.
- `puzzles/jigsaw` يقبل **أي مسار صورة** بلا `#cell` (يستعملها كاملة)، فالبوس يعمل بصورة خاصة: `image: "/art/c6/map-piece.webp"`.
- لكن شاشة المكافأة (`engine/MapPiece.tsx`) تقصّ من `map-full` فقط، فللفصل 6 تعرض قطعة خاطئة بصمت. الحل في EXPANSION_GAPS §5. لا تستعملي `#cell=7`: المركّب يقصّه إلى الخلية 6.

## 7) الرمز الجديد (`engine/symbols.ts`)
```ts
{ chapter: 6, id: "symbol-c6", name: "الريح", meaning: "…" },
```
- يُمنح عند إكمال `c6-l7` ويظهر في الحقيبة وشاشة المكافأة. أيقونته `items/symbol-c6.webp`.
- لو استعملته ألغاز لاحقة (مثل codelock) فاستعملي `icon: "symbol-c6"` وحدّثي `docs/SYMBOLS.md` بالترتيب الجديد للرحلة.

## 8) ما يتغيّر في الواجهة لدى إضافة الفصل
خريطة الرحلة الآن **5 محطات ثابتة** (مواضع ومسار SVG وصور ثابتة)، والعدّاد «/ 05» في الحقيبة والشاشة الأولى مكتوب يدوياً، والخاتمة تُعرَض بعد الفصل 5. الجدول الكامل بأماكنها وتقدير الجهد في `docs/EXPANSION_GAPS.md`. **لا تعدّلي المحرّك ضمن مهمة المحتوى**؛ تُبلَّغ B.

## 9) كيف يتحقق الفاحص (`npm run test:content`)
**يفحص:** تطابق id الفصل والملف؛ `mapPiece`؛ سقف 7 مستويات؛ id المستوى مقابل chapter/index؛ تكرار id المستوى والدليل؛ `title`/`objective`/`successText` غير فارغة؛ `difficulty` 1–5؛ `background` يبدأ بـ `/art/`؛ `hints` ثلاثة؛ `dialogue` 2–4؛ `clues` ≥2؛ البوس في المستوى 7 مع `reward`؛ وبحسب نوع اللغز: وجود معرّفات الحل بين العناصر (sequence وmatching وroute وdeduction وchoice وcodelock…)، طول الحل، تطابق `cipher` مع `detail`، وإمكان بلوغ هدف `balance`، وحدود إحداثيات `hotspot`، وحجم شبكة `tiles`، وعدد قطع `jigsaw`. ويحذّر من ألغاز بأقل من 100 احتمال.
**لا يفحص (اليدوي أعلاه):** وحدانية الحل، سريّة الحل، كفاية الأدلة، وجود الصور، تفرّد `mapPiece`/`reward` بين الفصول، وجود الشخصية في `CHARACTERS`، تطابق `speaker`، تتابع أرقام الفصول بلا فجوات، ووجود رمز الفصل في `SYMBOLS`.
`test:content` يشغّل أيضاً اختباراً ذاتياً (`check-content-selftest`) يضمن أن الفاحص يفشل فعلاً على محتوى مكسور (`scripts/fixtures/bad-content`).
