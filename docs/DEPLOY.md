# DEPLOY.md — نشر «سر النيل» على Vercel (لمازن)

لا تحتاجين معرفة سابقة بـ Vercel. الموقع ملفات ثابتة بلا خادم (والتنقل بين الشاشات عبر `#` في الرابط)، فالنشر بسيط ولا يحتاج أي إعداد توجيه (rewrites). الوقت المتوقع: 10–15 دقيقة.

## ما تحتاجينه قبل البدء
1. حساب **GitHub** يملك صلاحية على الريبو `mazinramos/sr-alnil`.
2. على الكمبيوتر: **Node.js الإصدار 22 أو أحدث** (من nodejs.org، نسخة LTS) و**Git**. للتحقق افتحي الطرفية واكتبي `node -v` (يجب أن يظهر `v22` أو أعلى) و`git --version`.
3. إنترنت.

## 1) تأكدي أن المشروع يُبنى عندك أولاً (دقيقتان)
في الطرفية:
```
git clone https://github.com/mazinramos/sr-alnil.git
cd sr-alnil/artifacts/nile-secrets
npm ci
npm run check
```
- `npm ci` يثبّت الحزم من القفل `package-lock.json`.
- `npm run check` يفحص الأنواع ثم يبني الموقع. يجب أن ينتهي بسطر `✓ built in ...` **بدون أي كلمة error**. لو فشل فلن ينجح النشر؛ أرسلي آخر سطور الخطأ لحساب B.
- (اختياري) لتجربة الموقع على جهازك: `npm run preview` ثم افتحي الرابط الذي يظهر (مثل `http://localhost:4173`).

## 2) الربط بـ Vercel (مرة واحدة)
1. افتحي **vercel.com** واضغطي **Sign Up**، ثم **Continue with GitHub** وسجّلي الدخول بحساب GitHub نفسه. اختاري الخطة المجانية (**Hobby**) إن سألك.
2. من لوحة التحكم اضغطي **Add New…** ثم **Project**.
3. ستظهر قائمة مستودعات GitHub. ابحثي عن `sr-alnil` واضغطي **Import** بجانبه.
   - **إن لم يظهر الريبو:** اضغطي **Adjust GitHub App Permissions** (أو Install)، ثم اختاري **Only select repositories** و`sr-alnil` واحفظي، ثم ارجعي للصفحة.
4. في صفحة **Configure Project** اضبطي الحقول بالضبط:
   | الحقل | القيمة |
   |---|---|
   | Project Name | أي اسم، مثلاً `sr-alnil` (يصبح جزءاً من الرابط) |
   | Framework Preset | **Vite** (يُكتشف تلقائياً غالباً) |
   | **Root Directory** | اضغطي **Edit**، اختاري المجلد `artifacts` ثم `nile-secrets`، واضغطي **Continue**. يجب أن يظهر `artifacts/nile-secrets` |
   | Build Command | `npm run build` (افتحي **Build and Output Settings** إن لم يظهر) |
   | Output Directory | `dist` |
   | Install Command | `npm install` |
   | Environment Variables | **اتركيها فارغة** (Firebase مؤجَّل ولا يحتاج شيئاً) |
   الملف `artifacts/nile-secrets/vercel.json` يضع القيم نفسها تلقائياً، لكن تأكدي منها بعينك لأن Root Directory هو الخطأ الأشهر.
   - **اختياري (للمشاركة على واتساب/فيسبوك):** صورة المعاينة `og:image` تحتاج عنواناً مطلقاً. على Vercel يُضبط عادةً تلقائياً من نطاق المشروع (يعتمد على خيار «Automatically expose System Environment Variables» في إعدادات المشروع، وهو مفعّل افتراضياً، ولم أستطع تجربته من بيئتي). لو استعملتِ نطاقاً خاصاً أضيفي متغيّراً باسم `SITE_URL` وقيمته نطاقك كاملاً (مثل `https://example.com`) ثم أعيدي النشر. بدونه تبقى المعاينة تعمل لكن بعض التطبيقات قد لا تعرض الصورة.
5. اضغطي **Deploy** وانتظري حتى تظهر الشاشة الاحتفالية (دقيقة إلى ثلاث).
6. اضغطي **Continue to Dashboard** ثم الزر **Visit** (أو الصورة المصغّرة) لفتح الرابط. شكله `https://sr-alnil-xxxx.vercel.app`. انسخيه وأرسليه لحساب A.

## 3) بعد الربط: التحديثات تلقائية
كل `git push` إلى فرع `main` ينشر نسخة جديدة خلال دقيقة أو دقيقتين، والرابط لا يتغيّر. تجدين حالة كل نشر في تبويب **Deployments** (أخضر = نجح، أحمر = فشل). أي فرع آخر يأخذ رابطاً تجريبياً منفصلاً.

## 4) كيف تتأكدين أن النشر سليم (على الموبايل)
افتحي الرابط الرئيسي (الذي ينتهي بـ `.vercel.app` بدون أي إضافة) ثم اختبري بالترتيب:
1. الشاشة الأولى بالعربية من اليمين لليسار، بلا نص إنجليزي ظاهر، ولا صورة مكسورة، وعنوان التبويب «سرّ النيل».
2. زر «ابدئي/مواصلة الرحلة» يفتح خريطة الفصول. الفصل الأول مفتوح والباقي مقفل (على حساب جديد).
3. افتحي المستوى الأول وحلّيه: تظهر النجوم وزر المتابعة.
4. **أغلقي التبويب كلياً وافتحي الرابط من جديد**: يبقى التقدّم محفوظاً.
5. افتحي مباشرةً رابطاً داخلياً مثل `الرابط#/map`: يجب أن يفتح الخريطة (لا 404). هذا يؤكد أن التوجيه بالـ hash سليم ولا حاجة لإعدادات إضافية.
6. لا تمرير أفقي في أي شاشة، والأزرار تُضغط بسهولة بإصبع واحد.
7. جرّبي من **هاتفين مختلفين** (أندرويد وآيفون إن أمكن).
8. اتبعي بعدها `docs/RELEASE_CHECKLIST.md` كاملة.

## فحص وسوم المشاركة (og:image) بعد النشر
تأكّدي أن صورة المعاينة تظهر عند مشاركة الرابط (واتساب وفيسبوك وتويتر). بعد كل نشر جديد:
1. **بالأمر** (من `artifacts/nile-secrets/`، ويحتاج Node 22+):
   ```
   npm run check:og -- https://رابط-موقعك.vercel.app
   ```
   يفحص: `og:image` و`twitter:image` عنوانان **مطلقان يبدأان بـ https**، والصورة تفتح فعلاً (نوعها صورة وحجمها ≤200KB)، والعنوان والوصف و`theme-color`، والأيقونتان. ينتهي بـ «✓ وسوم المشاركة سليمة» أو يعدّ الفحوص الفاشلة.
2. **يدوياً:** افتحي الرابط في المتصفح، ثم `view-source:` قبل العنوان (أو Ctrl+U)، وابحثي عن `og:image`: يجب أن تكون قيمته `https://…/og-image.jpg`.
3. **لو بدأ بـ `/og-image.jpg` (نسبي):** Vercel لم يعرّض نطاق المشروع للبناء. أضيفي في Vercel ← Settings ← Environment Variables المتغيّر `SITE_URL` وقيمته رابط موقعك كاملاً بلا `/` في آخره، ثم **Redeploy**، وأعيدي الفحص. (التطبيقات تخزّن معاينة الرابط؛ بعد التصحيح استعملي أداة «Sharing Debugger» في فيسبوك لإعادة الجلب.)

**سجل النتائج** (يملؤه من نشر أو فحص):
| التاريخ | الرابط | `og:image` يبدأ بـ https؟ | نتيجة `check:og` |
|---|---|---|---|
| — | — | **لم يُفحص بعد** | بانتظار أول نشر على Vercel. لا يوجد رابط منشور في المستودع، وبيئة حساب B لا تصل إلى نطاقات vercel.app، فلم أستطع الفحص بنفسي. الأمر جُرِّب على نسخة محلية فقط (نجح مع `SITE_URL`، وفشل بدونه كما هو متوقع) |

## لو ظهرت مشكلة
| العَرَض | السبب المحتمل والحل |
|---|---|
| **Build Failed** (أحمر) | افتحي النشر الفاشل ثم **Build Logs** وانسخي آخر 20 سطراً لحساب B. جرّبي `npm run check` محلياً: غالباً يفشل عندك أيضاً |
| الصفحة بيضاء | Root Directory ليس `artifacts/nile-secrets`. اذهبي إلى Settings ثم General ثم Root Directory وصحّحيه، ثم Deployments ثم Redeploy |
| `404: NOT_FOUND` على الصفحة الرئيسية | Output Directory ليس `dist`، أو Root Directory خطأ |
| صور مكسورة أو مستويات بلا خلفية | الملف غير موجود في `public/art`. راجعي `docs/MISSING_ASSETS.md` (تُولَّد بـ `npm run report:assets`). لا مشكلة تقنية، المستوى يعرض صورة بديلة |
| الخط غير جميل | الخط يُحمَّل من Google Fonts ويحتاج إنترنت؛ جرّبي شبكة أخرى |
| الرابط يعرض نسخة قديمة | انتظري دقيقتين بعد آخر push، وأعيدي تحميل الصفحة مع مسح الكاش. تأكدي أن آخر نشر أخضر |
| أدوات `#/preview` لا تفتح على الرابط المنشور | هذا مقصود: تعمل مع `npm run dev` فقط، والرابط المنشور يعيدها إلى الشاشة الأولى |
| `npm ci` يشتكي من Node | حدّثي Node إلى 22 أو أحدث |

## قبل التسليم النهائي (الاثنين)
- بعد تجميد الكود (G3) تأكدي أن آخر نشر على `main` أخضر، وأعيدي قائمة الفحص أعلاه كاملة على هاتفين.
- أرسلي الرابط النهائي لحساب A مع ملاحظة أي خلل متبقٍّ.
