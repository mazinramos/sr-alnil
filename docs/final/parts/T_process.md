# منهج العمل والفريق

## هيكل الفريق
عمل المشروع بفريق من ستة مساهمين بأدوار منفصلة، وقائد المشروع يحدّد الاتجاه والقرارات:

| الدور | المسؤولية |
|---|---|
| **قائد المشروع** | الفكرة والتصميم المرجعي والمواعيد، توليد الصور وقبولها أو رفضها، ربط المستودع والنشر، التجربة على الأجهزة |
| **المشرف (A)** | المراجعة والدمج، أدوات التحقق، المحتوى في الفصلين الأخيرين، تحويل الصور، القرارات المشتركة |
| **المحرك والواجهة (B)** | المحرك، الشاشات، الحفظ والتنقّل، الإتاحة |
| **الفصل الأول والاختبار الشامل (C)** | محتوى الفصل 1، اختبار اللعب الآلي، فحوص اللمس |
| **الفصل الثاني (D)** | محتوى الفصل 2 وجزء من الفصل 5، قراءة اللاعب |
| **الفصل الثالث (E)** | محتوى الفصل 3 وجزء من الفصل 4، التدقيق في الحقائق |
| **الإخراج الفني (F)** | الهوية البصرية وبرومبتات الصور، القراءة الثانية للوضوح |

## الأدوات المستخدمة
| الفئة | الأداة | الاستخدام |
|---|---|---|
| البرمجة | VS Code وTypeScript وVite | بناء وتشغيل المشروع |
| المساعد البرمجي والكتابة | Claude (Anthropic) | كتابة جزء كبير من الكود والنصوص والوثائق ومراجعتها، ضمن ستة حسابات بأدوار مفصولة |
| الصور | Gemini (توليد الصور) | الخلفيات والشخصيات والأغراض، من برومبتات مكتوبة لكل صورة |
| الإدارة | Git وGitHub | تاريخ المشروع والتعاون |
| النشر | Vercel | استضافة ونشر تلقائي |
| الاختبار | Playwright | لعب آلي كامل في متصفح حقيقي |

**شفافية:** استعنّا بالذكاء الاصطناعي في الكود والنصوص والصور، ونصرّح بذلك بوضوح. بقي بيد البشر: الفكرة، والاتجاه، وقبول كل صورة أو رفضها، والقرارات التي تغيّر المنتج، والتجربة على جهاز حقيقي. ولم نعتبر شيئاً منجزاً قبل أن يمرّ بفحص آلي أو قراءة مراجع آخر.

## كيف نظّمنا العمل
- **عقد مكتوب (`CONTRACT.md`):** يثبّت الأنواع والبنية وملكية الملفات. لكل مساهم مجلداته، فلا يكتب اثنان في ملف واحد.
- **بيانات لا كود للمحتوى:** يكتب كل مساهم فصله دون أن يلمس المحرك.
- **تقرير موحَّد لكل جولة:** ما أُنجز، والملفات، ورقم آخر commit، والمشاكل، وما يحتاجه من غيره.
- **تاريخ git:** كل commit يحمل حرف صاحبه في رسالته، فيُعرف من فعل ماذا.

## طبقات المراجعة
1. **فاحص المحتوى:** يرفض المستوى بلا دلائل كافية أو بحلّ مستحيل أو بتلميحات غير ثلاثة أو بشخصية غير معرّفة أو برمز قد يظهر إيموجي ملوّناً.
2. **قراءة لاعب:** مساهم يقرأ مستويات غيره كلاعب لا يعرف الحل، ويسجّل التلميح الذي يكشف الجواب أو الدليل غير المفهوم.
3. **مراجعة البرومبتات مقابل الكود:** تُطابق كل صورة بدلائل مستواها قبل التوليد.
4. **فاحص اللهجة:** يلتقط الفصحى والمفردات غير السودانية.
5. **لعب آلي كامل:** يمرّ على المستويات الخمسة والثلاثين في متصفح حقيقي بحلولها الصحيحة وبأخطاء متعمَّدة.

## أخطاء حقيقية وجدناها وعالجناها
| المشكلة | كيف عولجت |
|---|---|
| صورة لا تطابق الدلائل (c3-l5): الكود يطلب خيطاً وإبريقاً والصورة خرز وجرس | أعدنا بناء اللغز على ما في الصورة، وصارت القاعدة: ما يعتمد عليه اللغز يُكتب في برومبت الصورة قبل التوليد |
| تلميح يكشف الحل مباشرة | أُعيدت صياغة التلميحات لتتصاعد تدريجياً |
| صورة (c5-l3) لا يظهر فيها خط النهر الذي يقوم عليه اللغز | أُعيد توليدها بخط ظاهر وأُعيد قياس الإحداثيات |
| رموز تظهر إيموجي ملوّناً على الهاتف | استُبدلت بأشكال هندسية وأُضيف فحص آلي يمنعها |
| لغة الواجهة والمحتوى فصحى | حُوّلت إلى الدارجي السوداني بقواعد مكتوبة وفاحص، دون المساس بأي حل |
| تعارض مفردات (الماء/الموية، الغرفة/الأوضة) | قرارات توحيد مكتوبة في دليل الأسلوب |
